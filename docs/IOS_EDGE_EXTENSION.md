# v0.3：iOS 风格边缘扩展

## 为什么 v0.2 看起来像“照片卡片 + 模糊背景”

v0.2 的流程是：

```text
整张原图 -> 放大并模糊 -> 全屏背景
整张原图 -> contain 缩小 -> 清晰前景
最后叠在一起
```

这会天然产生：

```text
模糊背景
  └─ 一个完整、较小的清晰矩形
```

也就是用户反馈的“把原图塞进一张更大的模糊后的相同图片”。

这不是旧 iOS 的边缘扩展逻辑。

---

## v0.3 的正确流程

新流程是：

```text
最终画布
┌─────────────────────────┐
│     只在这里模糊扩展      │  <- extend_top
├─────────────────────────┤
│                         │
│      清晰原图主体         │
│                         │
│                         │
└─────────────────────────┘
```

处理步骤：

```text
1. 先确定“清晰内容区域”
2. 原图使用 COVER 填满清晰区域
3. 宽高比不同时，只裁掉多余部分
4. 从清晰区域的边缘像素向外 reflect
5. 只把外扩部分高斯模糊
6. 把清晰内容原样贴回
```

关键是：

> 清晰原图本身就是壁纸主体，不再是一张悬浮在模糊背景上的小卡片。

## 参考图的几何关系

示例原图：

```text
2048×1152
```

示例锁屏：

```text
944×2048
```

通过图像特征对齐可以看出，锁屏中的清晰部分大约从：

```text
y ≈ 531
```

开始。

也就是说：

```text
顶部扩展 ≈ 531px
清晰区域 ≈ 944×1517
```

原图被放大约：

```text
1.316x
```

形成约：

```text
2695×1517
```

的图像，再从左右裁切成：

```text
944×1517
```

最后放到画布下部。

因此示例并不是“把完整横图缩小后放进竖屏”。

它实际上选择了：

> 保持主体尺寸 + 裁掉左右 + 只给顶部增加模糊延伸。

这就是 v0.3 采用 COVER 而不是 CONTAIN 的原因。

## 如何升级现有 v0.2

覆盖两个文件：

```text
src/upscaler/wallpaper.py
src/upscaler/wallpaper_cli.py
```

然后更新：

```text
src/upscaler/app.py
src/upscaler/__init__.py
pyproject.toml
tests/test_wallpaper.py
```

最简单的方法是直接把补丁 ZIP 解压到项目根目录并覆盖同名文件。

## 推荐参数

对于“横图改成 iPad 竖屏，并给顶部锁屏时间留空间”：

```text
扩展：
只向上 25%

横向裁切焦点：
居中

纵向裁切焦点：
居中

模糊：
64px

扩展区域亮度：
100%
```

如果主体不在中央：

```text
横向裁切焦点
```

是最重要的参数。

例如人物在原图右侧，可以选择：

```text
偏右
```

避免 COVER 裁切时把人物切掉。

## 一个不能同时满足的几何约束

对于 16:9 横图和 3:4 / 手机竖屏：

下面三件事无法同时做到：

1. 完整保留整张横图
2. 让清晰原图铺满竖屏宽度和大部分高度
3. 只在顶部增加一条模糊扩展

必须牺牲其中一个。

旧 iOS 示例选择的是：

```text
保留主体
+ 铺满竖屏
+ 顶部扩展
- 裁掉横图左右两侧
```

因此 v0.3 默认采用 COVER 裁切，这是有意为之，不是 bug。
